# 엔딩 군중: 스트리밍 대응

## 동작 범위

`SpawnEndingCrowd()`를 호출하면 현재 게임 월드에 엔딩 상태를 한 번 활성화합니다. 플레이어 시작 위치와 관계없이, 이후 로드되거나 생성되는 살아 있는 `EnemyCharacter` 중 `EndingCrowdTarget` Actor Tag가 있는 대상도 사람으로 대체합니다.

미로드 지역의 사람을 모두 미리 생성하거나 시뮬레이션하지는 않습니다. 해당 지역이 로드되면 몬스터를 먼저 숨기고 전투를 막은 상태에서 NavMesh와 군중 생성을 준비합니다. 따라서 로딩 동안 잠깐 사람이 없는 구간은 생길 수 있지만, 엔딩 이후 새로 로드된 적이 전투에 참여하지 않게 합니다.

월드 단위 상태이므로 World Partition 셀이나 제어 액터가 언로드되어도 엔딩은 유지됩니다. 플레이 종료, 맵 재시작, 다른 맵으로 이동하면 초기화합니다. SaveGame이나 재접속 복원은 사용하지 않습니다.

## 에디터 설정

1. 에디터를 닫고 Editor 타깃을 직접 빌드한 뒤 `TinoKingdom_ByChanWoong` 맵을 엽니다.
2. 기존 `TinoEndingCrowdController`와 `TinoEndingCrowdSpawner`는 그대로 사용합니다. 두 액터의 **Is Spatially Loaded는 꺼둡니다.** 비활성화되는 Runtime Data Layer에는 넣지 않습니다.
3. 스포너의 `Entity Types`는 하나, `Entity Config`는 `DA_TinoCrowdEnding`, `Proportion`은 1.0으로 둡니다. `Auto Spawn on Begin Play`는 끕니다.
4. 전환 모드에서 배치된 스포너는 **설정 원본**입니다. 직접 군중을 생성하지 않습니다. Count나 EQS 생성기를 추가로 설정할 필요가 없습니다. 기존 EQS 설정이 남아 있어도 전환 모드에서는 사용하지 않습니다.
5. 제어 액터의 `Crowd Spawner`는 위 스포너, `Transform Tagged Monsters`는 참, `Target Monster Tag`는 `EndingCrowdTarget`으로 둡니다.
6. 몬스터는 **Is Spatially Loaded를 켠 기존 스트리밍 설정을 유지**합니다. 테스트 때문에 몬스터 전체를 항상 로드하도록 변경했다면 원래 설정으로 돌립니다. 실제 몬스터 액터에 Actor Tag를 붙이며, 몬스터 스포너나 Component Tag에 붙이는 것으로는 대체되지 않습니다.
7. 테스트할 때만 제어 액터의 `Test Spawn on Begin Play`를 켜고 `Test Spawn Delay`를 5초로 설정합니다. 테스트 후에는 끕니다.
8. 각 지역에 군중이 걸을 수 있는 NavMesh가 필요합니다. 코드가 NavMesh나 지형을 대신 생성하거나 강제로 로드하지는 않습니다.

## 코드 구조

- `TinoEndingCrowdController`: 엔딩 상태 활성화 및 기존 완료/실패 이벤트를 전달합니다. 일반 군중 생성 테스트 모드도 유지합니다.
- `TinoEndingCrowdSubsystem`: 게임 월드 동안 엔딩 상태와 대상별 진행 상황을 보관합니다. 0.25초마다 등록된 대상만 확인하며, 동시 군중 생성 요청은 최대 4개입니다.
- `EnemyCharacter`: BeginPlay에서 엔딩 상태를 확인하고 등록합니다. 늦게 로드된 대상은 블루프린트 BeginPlay 전에 숨김/전투 차단을 적용하고, 초기화 후 한 번 더 적용합니다. EndPlay에서는 대응 군중을 정리합니다.
- `EnemyAIController`: 몬스터 BeginPlay보다 소유 처리가 먼저 발생해도 엔딩 대상의 전투 트리를 시작하지 않습니다.
- `TinoEndingCrowdSpawner`: 설정 원본의 Entity Config를 복사한 런타임 스포너가 대상별로 한 명씩 생성합니다. 런타임 스포너는 Persistent Level에 생성하고 원본 몬스터의 로드 수명에 맞춰 명시적으로 정리합니다.

원본 몬스터 참조는 약한 참조이므로 군중 관리 때문에 원본 지역이 계속 로드되지는 않습니다. 대상 언로드 시 해당 군중과 비동기 생성 요청을 취소하고 등록을 지웁니다. 재로드되면 엔딩 상태를 다시 적용하여 새 군중 한 명을 생성합니다. 같은 액터의 중복 등록은 새 군중을 만들지 않습니다.

## 표시, 실패 및 완료의 의미

- 최초 요청 당시 로드된 대상은 AI/피해/충돌을 막되 사람 생성 확인 전까지 외형을 유지합니다. 이후 로드된 대상은 준비 중에도 숨깁니다.
- 생성이 완료되면 원본을 숨깁니다. 사망/경험치/드롭/처치 퀘스트 처리는 호출하지 않습니다.
- 한 몬스터의 NavMesh 준비 실패가 다른 몬스터의 전환을 취소하지 않습니다.
- `Transformation Timeout` 기본값 60초는 각 대상의 NavMesh 준비와 생성 단계에 각각 적용하는 게임 시간입니다. 생성 요청 차례를 기다리는 것만으로 시간 초과시키지는 않습니다.
- 실패 시 해당 군중만 정리하고 엔딩 상태와 원본의 전투 차단을 유지합니다. 최초 대상은 정지한 외형이 남을 수 있고, 늦게 로드된 대상은 계속 숨겨져 있습니다.
- 문제 해결 후 플레이 중 제어 액터의 **Retry Failed Crowd Conversions** 버튼 또는 같은 이름의 C++/Blueprint 함수를 호출하면 실패한 대상만 재시도합니다. 성공한 군중은 다시 생성하지 않습니다.
- `OnMonstersTransformed`와 `OnCrowdSpawningFinished`는 최초 요청 당시 로드된 대상의 처리가 끝났을 때 한 번 발생합니다. 처음 대상이 0명이거나, 미완료 대상이 언로드되어 더 이상 기다릴 대상이 없어져도 완료될 수 있습니다. 맵 전체 또는 GPU 준비 완료를 뜻하지 않습니다.
- `Ending World Active`는 월드 상태 활성화 여부입니다. `GetLoadedCrowdCount()`는 현재 준비된 군중 수, `GetPendingCrowdCount()`는 대기/생성/실패 상태의 대상 수를 반환합니다.
- Output Log의 `LogTinoEndingCrowdSession`에서 대상별 완료/실패를, 제어 액터의 `Last Spawn Error`에서 최근 실패 이유를 확인합니다.

## 검증 체크리스트

1. 가까운 지역 A에서 시작해 엔딩을 발동하고 해당 지역 군중 생성 확인.
2. 시작 시 미로드였던 지역 B로 이동: 태그 대상이 몬스터로 싸우지 않고 사람으로 생성되는지 확인.
3. A가 언로드될 만큼 멀어졌다가 재방문: 몬스터 부활 및 중복 군중이 없는지 확인. 여러 번 반복하여 런타임 스포너가 계속 누적되지 않는지 확인.
4. B에서 시작하는 테스트도 진행: 시작 위치를 바꿔도 A/B에 같은 엔딩 상태가 적용되는지 확인.
5. NavMesh가 없는 대상 하나와 정상 대상 여러 개로 테스트: 정상 대상은 전환되고 잘못된 대상만 오류를 보고하는지 확인.
6. 군중 생성 대기 중 지역 이탈: 나중에 해당 위치에 고아 군중이 생기지 않는지 확인.
7. 엔딩 활성화 당시 대상이 없는 장소에서 시작한 후 대상 지역으로 이동해도 전환되는지 확인.
8. 플레이 종료 후 재시작하고 테스트 자동 호출을 끈 상태에서는 엔딩 전 몬스터로 정상 시작하는지 확인.
9. 기존 `Transform Tagged Monsters = false` 일반 생성 테스트 경로 확인.

자동화 테스트 `TinoKingdom.EndingCrowd.StreamingRegistration`을 추가했습니다. 태그 필터, 거리 독립 등록, 중복 등록, 등록 해제와 동일 액터 재등록, 월드 종료 상태 정리를 검증하는 테스트입니다. 실제 World Partition 스트리밍, Mass 생성과 렌더링은 위 수동 테스트가 필요합니다. 이번 작업에서는 빌드와 테스트 실행을 하지 않았습니다.

## 아직 포함하지 않은 기능

- 변신 이펙트, 엔딩 시퀀스 연결 및 촬영 영역의 사전 로딩/렌더링 준비
- 재접속 저장, 맵 이동 간 엔딩 상태 전달, 멀티플레이 동기화
- 지역 재방문 시 동일한 얼굴/의상 및 마지막 배회 위치 보존: 현재는 원본 몬스터 위치에서 새 군중을 생성하므로 달라질 수 있습니다.
